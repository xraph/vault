This guide walks you through installing Vault, storing an encrypted secret, evaluating a feature flag, and reading runtime configuration. By the end you will have a working program that exercises all three subsystems through the `vault.Vault` facade.

## Prerequisites

- Go 1.26 or later
- A Go module (`go mod init`)

## Install

```bash
go get github.com/xraph/vault@latest
```

This pulls in the root module and all sub-packages (`secret`, `flag`, `config`, `crypto`, `scope`, `store/memory`, etc.).

## Step 1: Create the Vault

`vault.New` takes a store, an app ID and a 32-byte AES-256 key, and wires the secret, flag, config, override, rotation and audit services over that one store. Start with the in-memory store for development and testing.

```go
import (
    "github.com/xraph/vault"
    "github.com/xraph/vault/store/memory"
)

key := []byte("0123456789abcdef0123456789abcdef") // exactly 32 bytes

v, err := vault.New(
    vault.WithStore(memory.New()),
    vault.WithAppID("myapp"),
    vault.WithEncryptionKey(key),
)
if err != nil {
    log.Fatal(err)
}
```

In production, read the key from the environment with `vault.WithEncryptionKeyEnv("VAULT_ENCRYPTION_KEY")`. The variable can be hex-encoded (64 characters) or base64-encoded. If you name a variable and it's missing or won't decode, `vault.New` fails rather than falling back to plaintext.

Leave the key out entirely and `vault.New` still works, but it stores secrets unencrypted and only says so as a warning on the logger you pass with `vault.WithLogger`.

## Step 2: Scope the context

Vault reads the app ID, tenant ID, user ID and client IP from `context.Context`. Set them once per request, usually in middleware:

```go
import "github.com/xraph/vault/scope"

ctx := scope.WithScope(context.Background(), "myapp", "tenant-1", "user-42", "10.0.0.1")
```

There are single-value setters too (`scope.WithAppID`, `scope.WithTenantID`, `scope.WithUserID`, `scope.WithIP`).

## Step 3: Store and retrieve a secret

```go
// Store a secret. The value is encrypted and auto-versioned.
// An empty app ID means the one Vault was built with.
meta, err := v.Secrets().Set(ctx, "openai-api-key", []byte("sk-abc123"), "")
if err != nil {
    log.Fatal(err)
}
fmt.Printf("stored: version=%d\n", meta.Version)
// Output: stored: version=1

// Retrieve and decrypt the secret.
sec, err := v.Secrets().Get(ctx, "openai-api-key", "")
if err != nil {
    log.Fatal(err)
}
fmt.Printf("value: %s\n", sec.Value)
// Output: value: sk-abc123

// Update the same key: the version increments.
meta2, err := v.Secrets().Set(ctx, "openai-api-key", []byte("sk-xyz789"), "")
if err != nil {
    log.Fatal(err)
}
fmt.Printf("updated: version=%d\n", meta2.Version)
// Output: updated: version=2
```

## Step 4: Evaluate a feature flag

Define flags through `v.FlagManager()` and read them through `v.Flags()`. Reads never return an error; they give you the default you pass when the flag is missing, disabled or the wrong type.

```go
import "github.com/xraph/vault/flag"

// Define a boolean flag.
if _, err := v.FlagManager().Create(ctx, flag.CreateInput{
    Key:          "new-dashboard",
    Type:         flag.TypeBool,
    DefaultValue: false,
    Description:  "Enable the redesigned dashboard",
    Enabled:      true,
}); err != nil {
    log.Fatal(err)
}

// No rules yet, so this returns the flag's default.
fmt.Printf("new-dashboard: %v\n", v.Flags().Bool(ctx, "new-dashboard", false))
// Output: new-dashboard: false

// Target tenant-1.
if _, err := v.FlagManager().SetRules(ctx, "new-dashboard", []flag.RuleInput{{
    Type:        flag.RuleWhenTenant,
    Config:      flag.RuleConfig{TenantIDs: []string{"tenant-1"}},
    ReturnValue: true,
}}); err != nil {
    log.Fatal(err)
}

// The context carries tenant-1, so the rule matches.
fmt.Printf("new-dashboard (tenant-1): %v\n", v.Flags().Bool(ctx, "new-dashboard", false))
// Output: new-dashboard (tenant-1): true
```

`RuleWhenTenant`, `RuleWhenUser`, `RuleRollout` and `RuleSchedule` work. `RuleWhenTenantTag` and `RuleCustom` are accepted but never match yet. See [Feature flags](/docs/subsystems/feature-flags).

## Step 5: Read runtime config

```go
import (
    "time"

    "github.com/xraph/vault/config"
)

// Set a config entry.
if err := v.Config().Set(ctx, "rate-limit", 100, "",
    config.WithDescription("Max requests per minute"),
); err != nil {
    log.Fatal(err)
}

// Read with type-safe accessors.
fmt.Printf("rate-limit: %d\n", v.Config().Int(ctx, "rate-limit", 50))
// Output: rate-limit: 100

// Set and read a duration.
if err := v.Config().Set(ctx, "request-timeout", "30s", ""); err != nil {
    log.Fatal(err)
}
fmt.Printf("timeout: %s\n", v.Config().Duration(ctx, "request-timeout", 10*time.Second))
// Output: timeout: 30s

// Watch for changes made through the service.
v.Config().Watch("rate-limit", func(ctx context.Context, key string, oldVal, newVal any) {
    fmt.Printf("config changed: %s %v -> %v\n", key, oldVal, newVal)
})
```

## Step 6: Switch to PostgreSQL

When you are ready for production, swap the memory store for PostgreSQL. The PostgreSQL, SQLite and MongoDB stores all take a `*grove.DB`:

```go
import (
    "github.com/xraph/grove"
    "github.com/xraph/grove/drivers/pgdriver"
    "github.com/xraph/vault/store/postgres"
)

drv := pgdriver.New()
if err := drv.Open(ctx, "postgres://user:pass@localhost:5432/mydb"); err != nil {
    log.Fatal(err)
}
db, err := grove.Open(drv)
if err != nil {
    log.Fatal(err)
}

pgStore := postgres.New(db)
defer pgStore.Close()

// Create the Vault tables. Idempotent, so safe on every start.
if err := pgStore.Migrate(ctx); err != nil {
    log.Fatal(err)
}

v, err := vault.New(
    vault.WithStore(pgStore),
    vault.WithAppID("myapp"),
    vault.WithEncryptionKeyEnv("VAULT_ENCRYPTION_KEY"),
)
```

Under Forge, the extension builds the store from your Grove database for you, but it doesn't run `Migrate`. Run it once yourself first; see the [Forge extension guide](/docs/guides/forge-extension).
